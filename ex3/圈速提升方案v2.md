# 圈速提升方案 v2（基于 refine2，目标：过掉 992m 出圈弯，跑完整圈，圈速 < 58.27s）

> 本文只写思路与参数，不改任何脚本/代码，全部用环境变量在 eval 时覆盖。
> 与上一版 `高速展示提速方案.md` 的根本区别：**上一版方向搞反了。**

---

## 0. 上一轮的关键发现（改写了整个方向）

复核 `runs/refine2_fast_ms210_b5aux_0612a/eval/episode_summary.csv`，三条硬事实：

1. **`guard_steps_ratio = 0.0`** —— 整局 guard **一步都没介入**。
2. 所有提速档（ms140~ms220、b6~b9）**全部在完全相同的 26.158s / 129 步 / `distFromStart=992m` 出圈**，逐字节一致。
3. refine2 的 152 **不是 guard 压出来的**，是 actor 策略自己的自由上限。

### 为什么上一轮怎么调都纹丝不动
上一轮最终参数里有 **`TORCS_CTH_PREVIEW_MIN_SPEED=210`**。看 `gym_torcs.py::apply_cth_preview_guard` 第 1494-1496 行：

```python
speed = self.safe_float(obs.get("speedX"))
if speed < params["min_speed"]:
    return action          # 速度低于 min_speed，guard 直接返回，完全不介入
```

车速从没超过 ~152，而 `min_speed=210` → **guard 整局被关死**。上一轮所有 `TARGET_SPEED_BASE`、`BRAKE_GAIN`、`CLEARANCE_START` 的调整都作用在一个根本没运行的代码分支上，所以结果永远是 152.045799 / 26.158s。

**结论：上一版是在"放开一个本来就没夹车的夹子"，方向反了。**

---

## 1. 真正的杠杆：让 guard 在 992m 弯之前减速

refine2 死因不是速度上限不够，而是**带着 152 直接冲进 992m 处的弯、完全不减速**（guard 没激活，actor 自己也不会为弯减速）。

整圈 g-track-1 ≈ 2545m，refine2 只跑了 992m（**39%**）。refine3 能跑完整圈是因为它会过弯（但直道慢，avg 124、best lap 58.27）。

**refine2 直道 152 是真本事**。只要能过掉 992m 那个弯、跑完整圈，圈速会显著快于 58.27。

所以 v2 的方向和上一版相反：**把 guard 重新激活、并让它在弯前主动减速**，牺牲弯前一点速度，换"活过弯 → 跑完整圈"。

## 2. 要拧的旋钮（方向全部与上一版相反）

| 环境变量 | 上一轮(错) | v2 方向 | 作用 |
|---|---|---|---|
| `TORCS_CTH_PREVIEW_MIN_SPEED` | 210（关死guard） | **80~100**（重新激活） | **第一优先**：低于此速 guard 不介入，必须调低让 guard 在 152 时是活跃的 |
| `TORCS_CTH_PREVIEW_TARGET_SPEED_BASE` | 230 | **150~165** | 直道封顶，略低于 152，让 guard 真的开始管速度 |
| `TORCS_CTH_PREVIEW_TARGET_SPEED_MIN` | 155 | **90~110** | 弯中允许降到的最低速，调低才能为急弯让出减速空间 |
| `TORCS_CTH_PREVIEW_CLEARANCE_START` | 50（更晚减速） | **70~80**（更早减速） | 前方净空多远开始减速，调高→更早因弯减速 |
| `TORCS_CTH_PREVIEW_TARGET_SPEED_BRAKE_GAIN` | 0.010（刹更轻） | **0.030~0.05**（刹更狠） | 超速时刹车强度 |
| `TORCS_CTH_PREVIEW_TARGET_SPEED_HARD_MARGIN` | 28（更晚硬刹） | **10~14**（更早硬刹） | 触发硬刹的超速阈值 |
| `TORCS_CTH_PREVIEW_HEADING_START_DEG` | 默认7 | **5~6**（更早因转向减速） | 航向角多大开始算风险 |

核心一句：**MIN_SPEED 必须先调低（否则 guard 永远不动），然后让 guard 早一点、狠一点地在弯前减速。**

## 4. 扫描网格（先验证 guard 能激活，再调到刚好过弯）

### Step A — 先证明 guard 能激活（单点）
```
名称: refine2_corner_g0
MIN_SPEED=90  TARGET_SPEED_BASE=160  TARGET_SPEED_MIN=100
CLEARANCE_START=70  BRAKE_GAIN=0.030  HARD_MARGIN=14
```
- 看 `guard_steps_ratio`：**若仍为 0** → MIN_SPEED 再降到 80、TARGET_SPEED_BASE 再降到 150，重跑，直到 ratio > 0。
- 看 `distFromStart`：和 992m 比，是更远（弯前减速起效）还是更近（减速过猛/转向被带偏）。

### Step B — 在 guard 已激活的基础上，调到"刚好过弯"
| 名称 | TARGET_SPEED_BASE | TARGET_SPEED_MIN | CLEARANCE_START | BRAKE_GAIN | 意图 |
|---|---|---|---|---|---|
| `refine2_corner_g1` | 160 | 100 | 75 | 0.035 | 弯前更早更狠减速 |
| `refine2_corner_g2` | 155 | 95 | 78 | 0.040 | 再狠一点 |
| `refine2_corner_g3` | 150 | 90 | 80 | 0.050 | 最保守过弯档 |

判定：
- `distFromStart` 突破 992m → 过了第一个弯，继续看下一个出圈点在哪、是否需要同样手法处理。
- `lap_count >= 1` → **已跑完整圈**，记下 `best_lap_time`，进入 Step C。
- 减速太猛导致 avg 掉太多 / 反而更早停（no_progress）→ 往回放松一档（BASE 调高、BRAKE_GAIN 调低）。

### Step C — 在"能完成整圈"的前提下抢圈速
一旦有一组能 `lap_count >= 1`：
- 把 `TARGET_SPEED_BASE` 往回抬（160→168→175…），`BRAKE_GAIN` 往回降，**在仍能跑完整圈的前提下**把直道速度尽量放高。
- 取 **能完成整圈、`best_lap_time` 最小** 的那一组 = 最终圈速展示版。
- 目标：`best_lap_time < 58.27`（打败 refine3 demo）。直道 152 的底子在，过弯后圈速应明显优于 124 avg 的 refine3。

---

## 5. 如果 guard 怎么调都救不了这个弯（回退判断）
若 Step A/B 充分尝试后：guard 一激活就把车带偏/逼停，或减速到能过弯时 avg 已掉到 refine3 水平以下——
说明 **refine2 这个 actor 本身不会过这个弯，guard 只能硬刹但救不了转向**。那么圈速提升不能靠纯 eval 调参，需要：
- 要么回退到"整圈用 refine3、高速展示用 refine2"的双版本交付；
- 要么走 `下阶段计划.md` 的 RL fine-tune（以 refine2 为 bootstrap，加 corner-aware 减速学习）——那是训练任务，不在本 eval 调参方案范围内。

**先把 §4 的 Step A/B/C 跑完再决定是否需要回退**，因为 guard 弯前减速这条路上一轮从没真正测过（一直被 MIN_SPEED=210 关死）。

---

## 6. 一句话总结
上一版方向反了：`MIN_SPEED=210` 把 guard 关死，所以怎么调都卡在 152/26s/992m。v2 反过来——**先把 MIN_SPEED 降到 80~100 重新激活 guard，让它在 992m 弯前主动减速**，用弯前牺牲一点速度换"过弯、跑完整圈"，再在能完成整圈的前提下把直道速度抢回去，目标 `best_lap_time < 58.27`。
