# 高速展示提速方案（基于 refine2，目标：均速 > 152、存活 > 20s）

> 本文只写"怎么在 152 的基础上继续提速"，不改任何脚本/代码，全部用环境变量在 eval 时覆盖。
> 验收口径（本任务专用，和 30s 主线无关）：**存活 > 20s 即可，不在乎结尾是否出圈，avg_speed 越高越好。**

- 该 checkpoint 的 eval 记录（`runs/cth_v1_gtrack1_refine2/eval/episode_summary.csv`）：

## 1. 提速原理（为什么拧这几个旋钮）

`gym_torcs.py::apply_cth_preview_guard` 里，速度被一个 **target_speed 封顶**钉住：

```
target_speed = target_speed_base
             - heading_gain  * |preview_heading|
             - clearance_gain* max(0, clearance_start - far_clearance)
             - track_bias_gain* track_bias
target_speed = clip(target_speed, target_speed_min, target_speed_base)
```

一旦 `speed - target_speed` 超过缓冲区，guard 就强制 `accel` 封顶并加 `brake`。

所以 refine2 的 152 不是 actor 的极限，而是**被 176 这个封顶压住的结果**。提速的本质就是：**把 `target_speed_base` 和 `target_speed_min` 抬上去**，让 guard 不再这么早刹车，actor 自己能放多快就放多快。

直接影响速度的 3 个旋钮（按效果排序）：

| 环境变量 | 默认 | 作用 | 提速方向 |
|---|---|---|---|
| `TORCS_CTH_PREVIEW_TARGET_SPEED_BASE` | 176 | 直道/开阔段的速度封顶 | **调高**（主旋钮） |
| `TORCS_CTH_PREVIEW_TARGET_SPEED_MIN` | 105 | 弯道/高风险段的速度下限 | **调高**（保住弯中也不过度减速） |
| `TORCS_CTH_PREVIEW_MIN_SPEED` | 120 | 低于此速 guard 完全不介入 | 可略调高，让 guard 更晚介入 |

辅助旋钮（如果只抬 base 还嫌 guard 刹太狠，再动这些）：

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `TORCS_CTH_PREVIEW_TARGET_SPEED_BRAKE_GAIN` | 0.020 | 超速时刹车强度，**调低**→刹得更温柔 |
| `TORCS_CTH_PREVIEW_TARGET_SPEED_HARD_MARGIN` | 18 | 触发硬刹的超速阈值，**调高**→更晚硬刹 |
| `TORCS_CTH_PREVIEW_CLEARANCE_START` | 66 | 前方净空开始减速的距离，**调低**→更晚因前方减速 |

> 注意：抬得越高越可能更早出圈。但本任务只要求存活 > 20s，所以可以放心往上扫，扫到存活掉破 20s 为止，取存活仍 > 20s 里 **avg_speed 最高** 的那一组做展示版。

## 3. 扫描网格（从保守到激进，逐档加，存活掉破 20s 就停）

> 先只动主旋钮 `BASE` 和 `MIN`，一档一档往上加。每跑完一组看 `average_speed` 和 `curLapTime`。

| 组名 (RUN_NAME) | TARGET_SPEED_BASE | TARGET_SPEED_MIN | 预期 |
|---|---|---|---|
| `refine2_fast_b0`（对照） | 176 | 105 | 复现 ~152 / 26s |
| `refine2_fast_b1` | 185 | 115 | 略快 |
| `refine2_fast_b2` | 195 | 125 | 更快 |
| `refine2_fast_b3` | 205 | 135 | 更快，存活可能开始掉 |
| `refine2_fast_b4` | 215 | 145 | 激进，观察是否仍 > 20s |
| `refine2_fast_b5` | 230 | 155 | 上限探测 |

判定逻辑：
- `curLapTime > 20` 且 `average_speed` 比上一档更高 → 继续往上加一档。
- 某档 `curLapTime <= 20` → 停止往上，回到上一档（仍 > 20s 且最快的那组）。
- 若到 b5 仍 > 20s 且仍在加速 → 继续往上开 b6/b7（BASE 每次 +15）。

### 3.1 如果只抬 BASE/MIN 速度上不去（guard 还在刹）
说明 guard 因 heading/clearance 风险在减速，再叠加辅助旋钮（在选定的 BASE/MIN 上加）：

```bash
TORCS_CTH_PREVIEW_TARGET_SPEED_BRAKE_GAIN=0.010 \   # 默认0.020，减半→刹更轻
TORCS_CTH_PREVIEW_TARGET_SPEED_HARD_MARGIN=28 \     # 默认18，更晚硬刹
TORCS_CTH_PREVIEW_CLEARANCE_START=50 \              # 默认66，更晚因前方净空减速
```

## 4. 取最终展示版

1. 从扫描结果里挑 **`curLapTime > 20` 且 `average_speed` 最高** 的那一组，记下它的全部 `TORCS_CTH_PREVIEW_*` 值。
2. 用同一组参数 **开可视化复跑一次** 给老师看：
   ```bash
   # 把上面命令里的 TORCS_VISIBLE=0 改成：
   TORCS_VISIBLE=1 DISPLAY=:1 \
   ```
   （`DISPLAY` 按本机实际值，参考 `run_final_30s_eval.sh` 里用的是 `:1`）
3. 这一组就是高速展示版：起点 refine2，avg_speed > 152，存活 > 20s。

---

## 5. 纪律（避免踩之前的坑）

- **不覆盖** `cth_v1_gtrack1_refine2`、`cth_v1_gtrack1_refine3_balanced2_cpu` 等已有目录，每组用新 `TORCS_RUN_NAME`。
- 始终带 `TORCS_STANDARDIZE_FIRST_RESET=0` + `TORCS_EVAL_WARMUP_EPISODES=1` + `TORCS_RELAUNCH_EVERY=0`（这套已被验证能避免首局分叉和 3101 卡死）。
- eval 是确定性的，`TORCS_EPISODES=1` 就够；想多确认可设 3，结果会一致。
- 本展示版只追求"高速 + 存活 > 20s"，**不要**拿它去对 30s 主线的 `5/5 success_30s` 验收口径，两者目标不同。

---

## 6. 一句话总结

refine2 的 152 是被 guard 的 176 速度封顶压出来的；把 `TARGET_SPEED_BASE`/`TARGET_SPEED_MIN` 一档一档抬高（必要时再放松刹车/净空旋钮），在确定性 eval 下扫到"存活刚好还 > 20s"的那一档，取其中 avg_speed 最高的一组，开可视化复跑，即为高速展示版。
