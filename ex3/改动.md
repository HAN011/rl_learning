# 相比上一版实验报告的新增改动说明

本文用于对比：

- 旧版实验报告：`DDPG_Torcs_PyTorch/report_materials/04_report_ready_full_draft.md`
- 当前阶段说明：`现阶段介绍.md`

核心结论是：当前版本已经不再是“保持原始 baseline 奖励不变，只做 DDPG 超参数调优”的实验，而是切换到了 **CTH 奖励函数与 preview guard 联合优化** 的新阶段。实验目标、评价指标、代码结构和结论重点都发生了明显变化。

---

## 1. 实验主线发生了根本变化

### 旧版报告的主线

旧版报告的核心主线是：

- 以 `baseline` 为原始对照组；
- 在 **不修改 baseline reward** 的前提下，得到 `baseline_tuned`；
- 用 `g-track-2` 做零样本泛化验证；
- 用 `push1` 说明“高收益但高风险”的额外续训结果。

旧版报告在开头就明确写到：

- “在**不修改 baseline 奖励函数**的前提下调出更稳定的 `baseline_tuned`”
- “在新赛道 `g-track-2` 上进行零样本验证”
- “保留一次额外续训得到的 `push1` 结果”

因此旧版报告本质上还是一份：

- `baseline -> baseline_tuned -> push1`
- “稳定性优先于极限奖励”
- “单赛道训练 + 跨赛道零样本验证”

的 DDPG 基线调参报告。

### 当前阶段的新主线

当前阶段已经明确切换到：

- 主线是 `CTH`，不是 `TAL`
- 主赛道固定为 `g-track-1`
- 目标优先级从“尽量稳定不出界”升级为“**先稳定完整一圈，再继续压圈速**”

也就是说，当前工作不再是旧报告里的“调出一个更稳定的 baseline_tuned”，而是进入了新的问题设定：

1. 修改奖励函数
2. 引入 preview guard
3. 重新定义最优 checkpoint 的评价标准
4. 从“能在赛道内维持一段时间”推进到“稳定单圈完成”

这属于实验目标层面的升级，而不是简单的参数微调续作。

---

## 2. 奖励函数设定发生了变化

### 旧版报告

旧版报告强调最终模型仍使用原始 `baseline reward`，即：

$$
r_t = v_t \cos(\alpha_t) - |v_t \sin(\alpha_t)| - v_t |p_t|
$$

其逻辑是：

- 奖励沿赛道方向前进
- 惩罚横向漂移
- 惩罚偏离赛道中心

这套奖励函数没有显式鼓励“完整圈数”或“圈速”，更偏向基础赛道保持。

### 当前阶段

当前阶段已经引入新的 `CTH reward` 分支，代码实现位于：

- `DDPG_Torcs_PyTorch/gym_torcs.py:985`

新增内容包括：

- 速度奖励 `speed_reward`
- 前进距离奖励 `progress_reward`
- 赛道中心偏移惩罚 `center_penalty`
- 平滑惩罚 `smooth_penalty`
- 赛道边缘惩罚 `edge_penalty`
- 高速贴边惩罚 `speed_edge_penalty`
- 外甩惩罚 `outward_penalty`
- 低推进惩罚 `low_progress_penalty`
- 航向惩罚 `heading_penalty`
- 完成一圈后的反向惩罚 `reverse_penalty`
- 单圈奖励 `lap_bonus`

特别重要的是，当前 CTH 奖励已经引入了“**post-lap**”思路，即：

- 一圈完成后，对后段航向失控更敏感
- 一圈完成后，对低推进和倒车进行额外惩罚

这和旧版报告“只强调主赛道稳定、不改 baseline reward”的实验范式有本质区别。

### 当前额外接入但尚未跑完的 reward 参数

`现阶段介绍.md` 明确提到，已经接入但还未完全做成长训练验证的参数包括：

- `TORCS_CTH_PROGRESS_SCALE`
- `TORCS_CTH_HEADING_PENALTY_START`
- `TORCS_CTH_HEADING_SPEED_SCALE`
- `TORCS_CTH_POST_LAP_HEADING_MULTIPLIER`
- `TORCS_CTH_POST_LAP_LOW_PROGRESS_SCALE`
- `TORCS_CTH_POST_LAP_REVERSE_SCALE`

这些参数都已经进入 `compute_cth_reward()`，说明当前版本相较旧报告新增了“后段圈后稳定性优化”的奖励设计。

## 3. 评价指标体系发生了升级

### 旧版报告的核心指标

旧版主要用以下指标评价模型：

- 平均总奖励
- 平均速度
- 平均步数
- 终止原因
- 是否 `out_of_track`

这套指标适合回答：

- 是否比 baseline 更稳定
- 是否更少冲出赛道
- 是否具备一定泛化能力

### 当前阶段新增的关键指标

当前阶段已经把评价重心升级到“单圈完成质量”，新增指标包括：

- `lap_count_sum`
- `best_lap_time`
- `distRaced_mean`
- `avg_damage_sum`
- `stall_like_count`

对应实现和记录逻辑位于：

- `DDPG_Torcs_PyTorch/gym_torcs.py:636-759`
- `DDPG_Torcs_PyTorch/test.py:505-548`
- `DDPG_Torcs_PyTorch/test.py:1039-1117`

这意味着当前实验不再只看“没出界多久”，而是开始系统关注：

- 是否真的跑完整圈
- 跑完一圈用了多久
- 是否碰撞
- 是否后期失控磨停

这是从“生存导向指标”向“竞速导向指标”的明显升级。

## 4. 最优结果的定义发生了变化

### 旧版最优结果

旧版报告中，最终最优模型是：

- `baseline_tuned`

其核心结论是：

- 比 `baseline` 稳定得多
- 在 `g-track-1` 上不再出界
- 在 `g-track-2` 上有一定零样本泛化能力
- 比 `push1` 更适合作为“可交付”模型

### 当前阶段最优结果

当前阶段最强 run 已变为：

- `cth_v1_gtrack1_refine3_balanced2_cpu`

其 best checkpoint 指标为：

- `best_lap_time = 58.27 s`
- `average_speed_mean = 124.348171`
- `distRaced_mean = 2545.06`
- `lap_count_sum = 3`

最终评测结果为：

- `5/5` 稳定完成 `1 lap`
- 终止原因为 `no_progress`

这些数据来自：

- `DDPG_Torcs_PyTorch/checkpoints/cth_v1_gtrack1_refine3_balanced2_cpu/best_checkpoint_metrics.csv`
- `DDPG_Torcs_PyTorch/runs/cth_v1_gtrack1_refine3_balanced2_cpu/eval/episode_summary.csv`

与上一阶段最强基线 `cth_v1_gtrack1_refine2` 相比：

- `average_speed_mean: 152.045799 -> 124.348171`
- `distRaced_mean: 1092.08 -> 2545.06`
- `lap_count_sum: 0 -> 3`
- 从 `5/5 out_of_track` 变成 `5/5 稳定完成 1 lap`

新的最优性不再体现为“速度更高”，而体现为：

- 虽然平均速度下降
- 但成功从“高速但跑不完整圈”进化为“稳定完成单圈”

这是当前版本相对旧报告最重要的实验结论变化。

## 5. 新增了 preview guard 这一层安全控制机制

旧版报告里并没有系统性的 preview guard 设计，主要还是依赖策略网络本身和奖励函数进行学习。

当前阶段新增了：

- `compute_track_preview()`：`DDPG_Torcs_PyTorch/gym_torcs.py:1164`
- `apply_cth_preview_guard()`：`DDPG_Torcs_PyTorch/gym_torcs.py:1186`

其作用是：

- 利用前方赛道传感器计算预瞄方向和净空
- 在高速或急弯风险场景下，提前调整油门、刹车和转向
- 在策略动作外层再套一层“保护壳”

这是当前版本和旧版最大的结构性改动之一，因为它意味着：

- 旧版是“纯 RL 策略控制为主”
- 新版是“RL 策略 + 预瞄安全保护”的混合控制思路

### guard 扫描带来的新增实验结论

当前阶段已经新增专门扫描脚本：

- `DDPG_Torcs_PyTorch/scan_cth_guard.py`

并得到新的经验结论：

- `balanced_2` 是当前最好的稳定性/速度平衡点
- 关键参数为：
  - `TORCS_CTH_PREVIEW_MIN_SPEED=120`
  - `TORCS_CTH_PREVIEW_CLEARANCE_START=66`
  - `TORCS_CTH_PREVIEW_TARGET_SPEED_BASE=176`
  - `TORCS_CTH_PREVIEW_TARGET_SPEED_MIN=105`
  - `TORCS_CTH_PREVIEW_HEADING_START_DEG=7`

这部分在旧版报告中完全不存在，属于新增的实验模块。

## 6. checkpoint 选择逻辑发生了变化

旧版报告默认还是“稳定性优先”的模型选择逻辑，强调不出界、步数更长、泛化更稳。

当前阶段在 `test.py` 中新增了：

- `CHECKPOINT_SCORE_MODE`
- `pace_first`
- `stability_first`

代码位置：

- `DDPG_Torcs_PyTorch/test.py:327-337`

新的规则是：

- 对 `cth*` 主线，默认采用 `pace_first`
- 对旧非 CTH 逻辑，保留 `stability_first`

这说明当前最优 checkpoint 的定义已经改变：

- 旧版更强调“不坏”
- 新版开始在“完成单圈”的基础上考虑“更快”

这是实验筛选标准层面的新增改动。

## 8. 赛道与泛化叙事发生了变化

### 旧版报告

旧版强调：

- 训练赛道是 `g-track-1`
- 零样本验证赛道是 `g-track-2`
- 重点之一是跨赛道泛化

### 当前阶段

当前阶段明确收缩主线：

- 训练/评测赛道统一回到 `g-track-1`
- 特别强调不要再混到 `g-track-2`
- 当前首要目标是把单圈稳定性做扎实

因此，当前版本的重心已经从：

- “跨赛道零样本泛化”

转为：

- “单赛道上先把单圈完整性和圈速做出来”

这也是实验叙事上的重要变化。并不是说泛化不重要，而是当前阶段把研究重点前移到了“主赛道稳定单圈”。

## 9. 新增了 CPU/GPU 差异这一工程发现

旧版报告里没有把 CPU/GPU 差异作为主要实验结论。

当前阶段新增的重要发现是：

- 同一 checkpoint
- 同一 guard 参数
- `CPU` 与 `GPU` 的轨迹表现会明显不同

现阶段总结给出的结论是：

- `CPU` 上的 `balanced_2` 可以稳定跑出长距离甚至完整一圈
- `GPU` 上会明显退化

这意味着当前 CTH 主线在工程上新增了一个非常重要的实验约束：

- 参数扫描优先用 `CPU`
- 保守续训优先用 `CPU`
- best checkpoint 固化优先用 `CPU`

这个结论对复现实验和答辩解释都很重要，属于旧报告中没有的新内容。

## 10. 对失败方向的认识更具体了

旧版报告虽然也分析了 `push1` 这种“高收益但高风险”的失败案例，但失败解释仍偏宏观。

当前阶段新增了更具体的失败路径分析：

### 10.1 放松 guard 提圈速失败

扫描结果表明：

- `control_refine3_balanced2` 还能稳定出圈
- `speedup_a / b / c / d` 全部 `lap_sum = 0`

结论是：

- 当前不能继续靠“放松 guard”提升圈速

### 10.2 直接 refine4 硬训失败

对 `cth_v1_gtrack1_refine4_laptime_cpu` 的实验表明：

- 没有超过 `58.27s`
- 后续 interval eval 退化到约 `1071m`

结论是：

- 当前继续直接硬训，会把已经学到的稳定单圈重新训坏

这比旧版报告对失败实验的解释更细、更贴近当前研究阶段。

## 11. 对 `no_progress` 的理解更加深入

旧版报告中，`no_progress` 更多被当作一种终止现象来统计。

当前阶段则已经对其进行了行为层面的复盘，得到新的理解：

- 第一圈其实已经完成
- 完圈后车辆还能继续高速推进一小段
- 随后姿态开始失控
- 速度从 `170+` 快速下掉
- 朝向逐步转成接近反向
- 最后在低速或接近静止状态下长时间磨停
- 最终触发 `no_progress`

因此当前版本新增的认识是：

- 当前瓶颈不再只是“急弯减速不够”
- 而是“**过圈后继续推进与姿态保持能力不足**”

这也是为什么当前又新增了 post-lap reward 项的原因。

## 13. 一句话总结本次改动

相较上一版实验报告，当前版本最大的新增改动不是“又调了一轮参数”，而是：

- 从 `baseline_tuned` 的原始奖励调参实验
- 升级为 `CTH reward + preview guard + 单圈完成/圈速评价`
- 并围绕 `g-track-1` 单圈稳定完成这一目标，建立了一套新的训练、筛选和分析方法

如果用一句更适合写进报告的话来概括，可以写成：

> 上一版实验的核心突破是“从频繁出界提升到可稳定在赛道内运行”；而当前阶段的核心突破则是“在修改奖励函数并引入预瞄保护机制后，首次实现了 `g-track-1` 上的稳定单圈完成，并开始将优化目标从生存稳定性推进到单圈圈速与圈后持续推进能力”。
