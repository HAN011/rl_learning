## 1. 下阶段目标（B 分支，条件触发）

在**不覆盖、不破坏**现有 demo 的前提下，得到一个**学习策略**（而非靠 guard 顶速度），满足：

1. `5/5 success_30s`、`0 out_of_track`、`0 collision`（硬门槛，不可退让）
2. `avg_speed > 130.363325`（严格超过当前 demo）
3. `mean_abs_steer_delta` 不显著高于基线 `0.078`（动作流畅性不退化）

只要拿到**任意一个** interval-eval checkpoint 同时满足 1+2，就算 B 成功；拿不到就回退 demo 交付。

## 2. 根因复盘 → 决定 B 的设计原则

| 失败根因（已确认） | 对 B 的设计含义 |
|---|---|
| BC 目标=策略自己/guard 的动作，BC 天花板=teacher 速度 | **BC 不能造速度**，它只能当"安全缰绳"；速度只能由 RL+奖励产生 |
| `lmbda=alpha/\|Q\|` 实际放大 RL 项，BC MSE≈0.01 压不住 | 重写 actor-loss：**RL 项归一化到单位量级，BC 作为显式有界缰绳** |
| `critic2` 克隆自 baseline critic，`min(Q1,Q2)≈Q1`，过估计保护失效 | **critic2 独立初始化**，让 TD3 的 min 真正生效 |
| 奖励在 speed=180 饱和、重罚偏离中心 → RL 的"提速"梯度指向冒进 | **打开 straight-bonus + 抬 speed_clip**，让"快"只有在"居中+对齐+前方开阔"时才高价值 |
| 漂移单调且快（ep19~29 就崩），且无诊断、看不到 RL/BC 比例 | **加诊断日志 + interval eval 每 5~10 局 + keep-best + 连续退化早停** |
| guard 把速度钉在 ~130，策略没机会学更快的过弯 | 训练时**适度放松 guard 速度上限**（提供更快但仍安全的动作空间），guard 仍在做安全壳 |

核心一句话：**B = RL（提速引擎）+ 放松的 guard（更快的安全包络）+ BC 缰绳（防漂移）+ 安全提速奖励（让 RL 朝对的方向）+ 严格 keep-best/早停（抓住好窗口）**。

## 3. 需要的代码改动（尚未做，属于实施阶段）

> 全部加新开关、默认保持旧行为，保证 `TORCS_TD3=0` 旧路径与 demo 复现不受影响。

### C1. 重写 actor-loss（核心）
当前：`actor_loss = -alpha/|Q| · Q.mean() + bc_loss`（RL 被放大）。
改为 **RL 单位归一化 + 显式 BC 缰绳**：
```python
rl_term = q_pi.mean() / q_pi.abs().mean().detach().clamp(min=1e-6)   # ≈ 单位量级
actor_loss = -rl_term + BC_WEIGHT * bc_loss                          # BC_WEIGHT 直接可调
```
- 新增 `TORCS_BC_WEIGHT`（缰绳强度，预计需 ~20~100，靠诊断日志标定）。
- 用新开关 `TORCS_TD3BC_MODE=leash`（默认 `legacy` = 现公式）切换，旧 run 仍可复现。
- 含义：缰绳在策略贴近安全流形时松（bc_loss 小）、偏离时收紧（bc_loss 增大），RL 始终只施加单位级推力。

### C2. critic2 独立初始化
- 新增 `TORCS_TD3_CRITIC2_INDEPENDENT=1`（默认 0=保持克隆，向后兼容）。
- 置 1 时 critic2 用 `init_weights` 随机初始化，使 `min(Q1,Q2)` 真正抑制过估计。

### C3. actor-update 诊断日志
- TD3 开启时，每隔固定步数打印并写入一个 `td3_diag.csv`：`rl_term`、`bc_loss`、`BC_WEIGHT*bc_loss`、二者比值、`q_pi.mean()`、`|q_pi|.mean()`。
- 目的：**直接看到缰绳松紧**，不再靠出圈结果反推。这是 `现阶段介绍.md` §8.5 早就要求的前置项。

### C4.（已就绪，无需改码）奖励提速项
- `gym_torcs.py` 的 straight-bonus 已实现，训练时用 env 打开：`TORCS_CTH_STRAIGHT_BONUS_SCALE`、`TORCS_CTH_SPEED_CLIP`。

## 4. 实施步骤（每步都有硬门槛，过不了就停/回退）

### Step 0 — 改码 + 静态自检
做 C1/C2/C3。`py_compile` + 一个不连 TORCS 的张量级数值自测（仿照上次 `td3_mathcheck.py`），确认新 loss/独立 critic/诊断三者无 shape/运行错误。

### Step 1 — 回退自检（必须先过）
`TORCS_TD3=0` 跑 5 局 eval，必须复现 demo `5/5 / 130.363325`，证明新开关没破坏旧路径。

### Step 2 — 诊断标定 smoke（10~15 局）
`TORCS_TD3=1 TORCS_TD3BC_MODE=leash TORCS_TD3_CRITIC2_INDEPENDENT=1`，guard 保持 a2，奖励提速项先**不开**。
- 看 `td3_diag.csv`：调 `TORCS_BC_WEIGHT` 使 `BC_WEIGHT·bc_loss` 在策略偏离时能与单位 RL 项**同量级或更大**。
- 门槛：interval eval 不得出现单调恶化；ep10 仍 ≥4/5。**标定到缰绳能压住为止**，否则不进 Step 3。

### Step 3 — 安全提速 probe（30~40 局，短）
在 Step 2 标定好的缰绳上：打开 `STRAIGHT_BONUS_SCALE`(从 0.5 起) + `SPEED_CLIP`(1.33) + **适度放松 guard**（`TARGET_SPEED_BASE` 177→185、`MIN_SPEED` 上调、`BRAKE_GAIN` 下调一档）。
- `EVAL_EVERY=5~10`、`30s_pace_first`、keep-best。
- **连续 2 档 interval eval 退化即早停**（避免重蹈 s0/C2 把算力烧在崩溃后）。

### Step 4 — 收获或回退
- 若有任一 best checkpoint 满足 `5/5 && avg>130.36 && steer_delta≲0.085` → 用验收口径（warmup=1、reset=0、relaunch=0、headless+visible）正式复测 5 局确认，B 成功，更新最终展示候选。
- 若 probe 始终拿不到（速度上不去或保不住 5/5）→ **B 不成立，回退 demo 交付**，并把该失败分支按规范标注（不覆盖既有 checkpoint）。

## 5. 验收判据与纪律

- **硬门槛**：任何阶段一旦正式 5 局复测掉出 `5/5` 或出现 `out_of_track/collision`，该候选作废。
- **keep-best**：沿用 `30s_pace_first`；它已被证明能抓住 s0c2 的 ep14 好窗口。
- **早停**：连续 2 次 interval eval 退化即停，省算力。
- **不覆盖**：所有新 run 用新 `RUN_NAME`（如 `cth_v1_td3bc_b1` …），绝不写入 `cth_v1_gtrack1_refine3_balanced2_cpu` 或 demo 相关目录。
- **诊断优先**：没有 `td3_diag.csv` 看到缰绳比例之前，不允许再开长 probe。

- **B 可能本就达不到 >130 且 5/5**：这是任务本身的难点（BC 不造速度、RL 提速天然不稳），不是工程 bug。计划已把"回退 demo"写成显式分支，不会因为追 B 而失去已有交付。
