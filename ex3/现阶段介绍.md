## 4. 已完成的关键实验

### 4.1 预瞄保护层探索

做过多种 `preview guard` 版本：

- `preview off`
- `brake only`
- `brake tuned`
- `earlyguard`

关键结论：

- 纯高速旧线：快，但急弯必出圈
- 过强保护：能把生存距离推很远，但速度掉太多
- `earlyguard` 直接续训失败很明显
  - run：`cth_v1_gtrack1_refine3_earlyguard`
  - best checkpoint 只有：
    - `distRaced_mean = 45.5197`
    - `average_speed_mean = 43.041373`

- 不能粗暴把保护壳改得更激进后直接从旧 checkpoint 续训

### 4.3 CPU/GPU 差异

这是非常重要的坑。

已经确认：
- 同一 checkpoint
- 同一 guard 参数
- `CPU` 与 `GPU` 跑出来的轨迹表现差异很大

已验证的现象：
- `CPU` 上的 `balanced_2` 可以稳定跑出长距离甚至完整一圈
- `GPU` 上会明显退化

结论：
- 这条 `CTH` 主线当前必须优先用 `CPU`
- 至少在参数扫描、保守续训、best checkpoint 固化阶段，应继续用 `CPU`

## 7. 现在对 no_progress 的理解

已经用当前最强 checkpoint 做过后段轨迹复盘。

关键现象：

- 第 `1 lap` 完成后，车还能继续一段高速推进
- 之后姿态逐步失控
- 速度从 `170+` 开始快速下掉
- 朝向转到接近反向
- 后面长时间以接近 `0` 的速度原地磨
- 最终触发 `no_progress`

因此：
- 当前瓶颈已经不是“急弯提前减速不够”
- 而是“完成一圈后，后续姿态和继续推进能力不稳定”
