#### 根因判断：RL 项压倒 BC 锚，critic 漂移后 actor 追坏 Q

当前 TD3+BC actor loss 的实际实现是：

```python
lmbda = alpha / q_pi.abs().mean().detach().clamp(min=1e-6)
bc_loss = ((pi - actions) ** 2).mean()
actor_loss = -lmbda * q_pi.mean() + bc_loss
```

这里最关键的理解是：

- `TORCS_BC_ALPHA_START/END` 在当前实现里不是直接的 BC 权重
- `alpha` 实际控制的是归一化后的 RL/Q 项强度
- `bc_loss` 是动作 MSE，策略接近 guard executed action 时可能只有 `0.01` 量级
- `-lmbda * q_pi.mean()` 的量级大约跟 `alpha` 同级，`0.5~2.5` 都可能比 BC 锚大 1 到 2 个数量级

这解释了本次现象：

- Stage B 只有 10 局，且 `alpha=2.5` 恒定，critic 还没明显漂移，所以 post eval 仍然 `5/5`
- Stage C 到 ep19 时 deterministic eval 已经退化，说明贪心策略比带噪训练 rollout 更早暴露漂移
- Stage C 到 ep40 左右时 `alpha` 已经退火接近 `0.5`，但 `0.5` 仍然远大于当前 BC MSE 的有效锚定量级
- critic 漂移后，actor 继续追逐变坏的 Q，逐步把策略拖出稳定区

因此，不能再把“增大 `BC_ALPHA_START`”理解为“加强 BC”。在当前代码里，增大 `alpha` 更可能是放大 RL 项。Fujimoto TD3+BC 里的 `alpha=2.5` 能工作，是建立在其状态/动作归一化、Q 尺度、BC MSE 尺度相对匹配的前提上；当前 TORCS 任务里 Q 是上百量级累计回报，而 BC MSE 很小，比例关系已经不同。
